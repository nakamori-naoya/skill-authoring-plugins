# skill-authoring

**利用者が単独で完了させたい一つの仕事を、自己完結したskillとして作成または更新します。** 対象repositoryの規約を読み、実際の利用場面、似て非なるもの、反例、境界事例から責務と判断規律を組み立てます。

## これは何か／何ではないか

これは、再利用可能な一つの能力を、発見可能で実行可能なskillへするためのauthoring skillです。

これは、複数skillの順序を設計するもの、plugin marketplace全体を設計するもの、repository規約を新設するもの、題材固有のdomain知識を補うものではありません。依頼がそれらに当たる場合は実装せず、該当する責務分類と、skill authoringから除外した理由を返します。

## 入力

- 作成または更新したい仕事と、期待する完了状態
- 対象repositoryと既存のplugin / skill source
- 利用者が明示した制約と、対象repositoryに既にある規約

## 出力

- 作成または更新した自己完結skill
- 「何を受け取り、何を完了状態として返すか」という責務一文
- 「何であるか」と「何ではないか」を並べた責務境界
- 各判断の条件、必須行動、成功判定、停止時の返却
- 実行した典型例・負例・境界例の検証結果
- 未確認事項または停止理由

## 設定

独自設定はありません。配置、manifest、検証commandは対象repositoryの規約を使います。規約がない場合は、配布単位の中で閉じる最小構成を選びます。

## 停止条件

- 一つの完了状態へ絞れず、独立した能力が複数残る
- 対象repositoryの規約と依頼が両立せず、利用者の選択が必要になる
- 更新対象が存在せず、推測で別のskillを変更することになる
- 判断条件を具体例と反例で区別できず、指示の解釈が複数残る
