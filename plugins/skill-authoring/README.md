# skill-authoring

**利用者が単独で完了させたい一つの仕事を、自己完結したskillとして作成または更新します。** 対象repositoryの規約を読み、実際の利用場面、似て非なるもの、反例、境界事例から責務と判断規律を組み立てます。

## これは何か／何ではないか

これは、再利用可能な一つの能力を、発見可能で実行可能なskillへするためのauthoring skillです。

これは、複数skillの順序を設計するもの、plugin marketplace全体を設計するもの、repository規約を新設するもの、題材固有のdomain知識を補うものではありません。依頼がそれらに当たる場合は実装せず、該当する責務分類と、skill authoringから除外した理由を返します。

## 入力と出力

作成または更新したい仕事と期待する完了状態、対象repositoryと既存のplugin / skill source、利用者が明示した制約と対象repositoryに既にある規約を受け取る。作成または更新した自己完結skillと、その責務一文、「何であるか」と「何ではないか」を並べた責務境界、各判断の条件と行動と成功判定、止まる条件と返すもの、実行した典型例・負例・境界例の検証結果、未確認事項または停止理由を返す。

## 設定

独自設定はありません。設定解決scriptや環境変数によるroot解決も持ちません。配置、manifest、検証commandは対象repositoryの規約を使います。規約がない場合は、配布単位の中で閉じる最小構成を選びます。

## 分からないとき

このskillは他人のrepositoryにあるskillを変えるので、依頼の意図、対象、守るべき規約のどれかが分からなければ、推測で書かずに止まり、何が分からないかと提案を返す。対象repositoryの規約と依頼が両立しないとき、更新対象が存在せず別のskillを推測で変えることになるときも止まる。独立した能力が複数残るときは今回の対象と別作業を分けて境界を返し、書いた後で利用者が読んで直せる設計上の選択は、最も筋の良い案を採り、採らなかった案とともに報告する。
