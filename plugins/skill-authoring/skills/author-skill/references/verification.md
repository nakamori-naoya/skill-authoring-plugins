# skillの振る舞いを検証する

構文検査とmanifest検査は必要だが、skillがよい判断をすることまでは証明しない。責務一文と、実際の入力、成果、停止、報告が一致するかを現実的な依頼で確かめる。

最低限、次の三種類を使う。

- 典型例: 想定する依頼から、一つの完了状態へ迷わず到達できる
- 負例: 似ているが責務外の依頼を、便利だからという理由で取り込まない
- 境界例: 条件を一つ変えたとき、含めるか止めるかを理由付きで判断できる

各fixtureでは、期待する分岐、行動、停止、成果を実行前に書く。二つの異なる結論が同じ指示で正当化できる場合は、どちらかを正解扱いせず、分岐条件を追加してから再実行する。

変更したscriptには、正常入力が通る試験と、不正入力が実際に失敗する試験を置く。scriptが拒否する制限には、制限を破ったfixtureを実行する。scriptを持たない判断規律には、負例と境界例を入力して期待する停止または分岐と一致するかを確かめる。成功時にstderrへ異常が出ていないことも確認する。

referenceは入口から読む時点が分かり、別referenceを先に読まないと理解できない連鎖を作らない。skillが外部plugin、前工程、開発repositoryだけにあるfileを暗黙に必要としていないか、配布directoryだけを別の一時場所へ置いた状態でも見直す。

最後に対象repositoryが定めた全検証を実行し、実行したもの、失敗を確認した負例、目視でしか確認できなかった判断、未確認事項を分けて報告する。
