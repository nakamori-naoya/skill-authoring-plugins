# author-skill が作った skill に共通する条件

この条件は、実行の担当が author-skill で作った skill の SKILL.md（以下、skill）と、実行の担当の最後の報告（以下、報告）を判定するためのもので、どの依頼にも当てる。依頼に固有の条件は、この後ろに続く。条件は判断の型だけを書き、正しい skill の中身は書かない。どの条件も、ほかの条件の出来や文体の好みでは判定しない。各条件の「重み」は点数にまとめるときの値で、判定の厳しさは変えない。重み3は利用者の原則の芯（判断の要だけを書く、一つの判断は一か所、案件の値を規律にしない、止まる基準）、重み2は skill の骨組み、重み1は細部である。skill が存在しない、または空のときは、それを読む条件はすべて FAIL とする。

実行の担当は、依頼の文（`materials/request.md`）と、手元の repository（`work/out/repo/`）だけを渡された。問いに答える利用者はいなかった。

## 判断の要と、書かないもの

### skill-judgment-only

重み: 3

skill を読む実行のエージェントは、考えれば分かることを自分で正しく判断できる、という前提で判定する。

PASS：skill の本文の大半が、エージェントが自分では外しやすい判断と、その理由である。考えれば分かる手順の列挙（「1. 読む 2. 書く 3. 保存する」の類で、順序にも判断にも意味が無いもの）、同じことの言い換え、網羅のためだけの項目の列挙、起きるかどうか分からない場合分け、書き手の身を守るための防御の注記が、本文の中心になっていない。

FAIL：本文の大きな部分（節一つ以上）が、判断を含まない手順、網羅のための列挙、防御の注記で占められている。または、判断に理由が無く、規則が並ぶだけになっている。FAIL にするときは、その節の見出しを挙げる。

### skill-owner-referenced

重み: 3

PASS：手元の repository の既存の skill が既に持っている判断を、この skill が別の言葉で書き直していない。その判断が要る場面では、既存の skill を名前で指している。この skill が「扱わない」「返す」と書いた先の入口は、手元の repository に実在する。

FAIL：既存の skill が持つ判断（repository の README と既存の SKILL.md を読んで確かめる）を、この skill が独自の文で持っている。または、実在しない入口へ返している。

### skill-no-case-values

重み: 3

手元の repository の AGENTS.md と README を読み、skill がどの範囲の人へ配られるかを確かめてから判定する。

PASS：依頼の中で、配られる範囲のうち一つのチームや一つの案件だけの値や道具（製品名、チャンネル名、URL を貼る決まり、件数など）が、この skill を使う全員への規律として書かれていない。skill に残すなら、判断を説明する例として置かれ、例であることが読み取れる。

FAIL：依頼の中の一つのチームの値や道具が、skill の規律（「必ず〜する」「〜に投稿する」の類）として書かれている。

### skill-stop-by-conclusion

重み: 3

PASS：skill の止まる基準が、「欠けた情報がその成果物の結論を変えるか」で書かれ、その skill の成果物にとって何が結論で何が細部かが具体的に書かれている。結論を変えない欠落は、仮説を明示して進むと読み取れる。

FAIL：止まる基準が無い。または、欠けたら何でも止まる、欠けても何でも進む、のように結論と細部の区別が無い。

## skill の骨組み

### skill-contrast-examples

重み: 2

PASS：skill の中心の判断の少なくとも一つに、似ているが別の行動になる例、はっきりした反例、条件を一つ変えると結論が切り替わる境界のどれかが添えられ、その差を生む条件が本文に書かれている。

FAIL：中心の判断が一行の定義か規則だけで、どこまで当てはまるかを決める例も境界も無い。

### skill-business-names

重み: 2

PASS：skill の節の名前と概念の名前が、その仕事をする人が会話で使う言葉である。作り手の仲間内でだけ通じる説明語や、「正本」「正式な定義」のように何を指すか分からない語を作っていない。

FAIL：その仕事をする人が使わない説明語や権威の語が、節の名前か中心の概念の名前になっている。

### skill-prose-structure

重み: 2

PASS：本文は見出しと地の文で構造を作り、理由と因果を文章で説明している。箇条書きは本当の並列か順序のある手順に、表は同じ属性を行で比べるときだけに使われている。

FAIL：節の中身の大半が箇条書きか表で、判断の理由や因果が文章で書かれていない。

### skill-tried-and-reported

重み: 2

PASS：報告に、試した例（主要な利用場面の典型、責務の外を取り込みそうな負例、結論が切り替わる境界のうち二つ以上）と、それぞれの結果が書かれ、確かめられなかったことが区別されている。試していないことを試したと書いていない。

FAIL：報告に試した例と結果が無い。または典型の一つだけである。

## 細部

### skill-reasoned-weight

重み: 1

PASS：太字、「必ず」「絶対」の類の強調が二か所以下で、使った箇所には同じ文に理由がある。規則の重みは、何を守るかの一文で伝えられている。

FAIL：強調が三か所以上ある。または理由の無い強調がある。

### skill-repository-convention

重み: 1

PASS：skill が手元の repository の規約（置き場、frontmatter の name と description、条件付きの詳細の置き場）に従っていて、報告に repository の検査の結果が書かれている。description に、いつ使うかと、扱わないことが書かれている。

FAIL：規約に反する置き場か frontmatter である。または、報告に検査の結果が無い。
