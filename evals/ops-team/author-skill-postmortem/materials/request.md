# 依頼：障害の振り返りの叩き台を作る仕事を skill にしてほしい

決済チームのリーダーからの依頼である。skill は、この repository から社内のほかの運用チームにも配られる。

障害が起きるたびに、エージェントに振り返りの叩き台を作ってもらっている。月に二、三回ある。毎回同じような指摘をしているので、`skills/write-postmortem/SKILL.md` として skill にしてほしい。skill 名は `write-postmortem` で決めてある。

叩き台は、振り返りの会議の前に参加者が読むものである。再発防止策の担当と期日は、会議で決める。

## これまでにあったこと

3月の決済の遅延の振り返りでは、エージェントが原因の欄に「担当者の確認不足」と書いた。会議は誰が悪かったかの話になり、仕組みの話ができなかった。

5月のログインの障害では、エージェントが原因を「証明書の期限切れ」の一つに絞った。実際には、期限切れを知らせる監視が無かったことと、証明書の更新を一人しかできなかったことも重なっていた。

どちらの振り返りでも、再発防止策が「今後は注意する」「確認を徹底する」になり、会議の後に誰も何もしなかった。

7月の振り返りでは、エージェントが担当者と期日まで埋めた叩き台を作り、会議の前に回覧された。担当に名前を書かれた人は、会議で決まったことだと思って作業を始めていた。

## 使い方と範囲

時系列は、この repository の `write-incident-timeline` で先に作っている。振り返りはその時系列を材料にする。

うちのチームでは、振り返りに Datadog のダッシュボードの URL を必ず貼り、Slack の #incident チャンネルに投稿している。

顧客に影響が出た障害のほかに、未然に防げたヒヤリハット（本番に出る直前に気付いた設定の誤りなど）も振り返りたいことがある。一方で、顧客にも本番にも影響の無い、開発環境の設定の直しのようなものは振り返らない。
