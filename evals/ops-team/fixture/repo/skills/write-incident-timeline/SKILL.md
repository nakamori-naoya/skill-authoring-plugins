# write-incident-timeline

障害の時系列は、後から原因を考える人が、事実と解釈を取り違えずに読めるためにある。

## 観測した時刻と、推定した時刻を分ける

アラートやログに残った時刻は観測した時刻として書き、人の記憶や前後関係から置いた時刻は推定と書く。推定を観測と同じ形で書くと、原因の分析が推定の上に積み上がり、後から崩れるからである。時刻はすべてタイムゾーン付きで書く。複数のシステムの時刻が混ざると、順序が入れ替わって見えるからである。

## 時系列に、原因の解釈を混ぜない

「設定を誤って変更した」ではなく「設定の値が A から B に変わった」と書く。誤りかどうか、なぜ起きたかは、時系列を読んだ人が判断することで、ここで決めると後の議論を縛るからである。

## 止まるとき

記録の所在が分からず、障害の始まりか終わりの時刻が一つも観測で得られないときは、時系列を作らずに、要る記録を返して止まる。始まりと終わりが分からない時系列は、影響の長さを誤らせるからである。
