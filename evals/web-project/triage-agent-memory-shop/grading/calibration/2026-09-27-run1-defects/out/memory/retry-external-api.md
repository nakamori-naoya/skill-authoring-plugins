決済の外部API（Stripe）の呼び出しが 429 か 503 を返したら、指数バックオフで3回まで再試行する。間隔の上限は2秒にする。

**Why:** 4月に、決済APIが一時的に 503 を返したとき、再試行しない実装だったため注文が失敗扱いになり、顧客に二重に請求の案内が届いた。Stripe の文書は、429 と 503 は再試行してよく、再試行には同じ冪等キーを付けるよう求めている。

**How to apply:** 外部APIのクライアントを書くときは、再試行の対象の応答と冪等キーを確かめる。
